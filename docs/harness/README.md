# 学习系统项目知识库

这是接入 Harness 的第一步：为需求分析提供可核对的项目上下文与验收标准。
当前阶段是离线知识准备；企业微信、DeepSeek、技能执行器和学习记录上报尚未接通。

## 从这里开始

1. 阅读 [项目地图与业务说明](project-guide.md)。
2. 运行 `pnpm run knowledge:check`，确认知识与当前源文件一致。
3. 使用 `pnpm run knowledge:context -- words review` 获取相关模块上下文。
   不确定模块时省略参数，返回完整模块地图；工具不会凭关键词自动决定执行。
4. 将 [分析指令](analyst-instructions.md) 与返回的 JSON 一起提供给分析模型。
5. 模型按 [需求分析格式](request.schema.json) 输出分析，按
   [验收方法](acceptance.md) 评审；分析记录本身不触发文件修改。

`knowledge.json` 是可检索事实、规则和证据索引。`source-manifest.json` 记录审阅基线、
发布版本以及源文件 SHA-256。检索前会检查版本、文件指纹、证据锚点和引用关系；
失败时停止输出上下文，提示重新核对。文件指纹只能检测变化，不能证明文档语义正确。

`analysis-cases.json` 的 20 个案例是合成验收输入与评审参考，供评测方使用，
不进入 `knowledge:context` 输出。它们不包含真实学习者记录、密钥或浏览器状态。
离线检查通过不代表 DeepSeek 已通过需求理解验收。

## 更新知识

代码修改者检查受影响的模块、规则、证据和案例，解决代码与项目约定的冲突后，运行：

```powershell
pnpm run knowledge:refresh
pnpm run knowledge:check
pnpm test
```

`knowledge:refresh` 仅重建指纹，并不自动理解代码或更新事实。必须先完成内容审阅。
审阅基线是刷新时的 HEAD，交付版本来自 package.json；不会把尚未提交的改动谎称为
该 HEAD 已包含的代码。源文件使用统一 LF 换行计算指纹，兼容 Git 的跨系统换行设置。
新增业务文件需要登记到 sources；每次接任务还应核对实际变更范围，避免遗漏未索引能力。
